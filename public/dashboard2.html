Model lab · backtest & baseline comparison

Every monthly target is backtested one month ahead with six candidates: last value, 3-month average, same month last year, seasonal × growth, a regularised Ridge (trend + annual cycle) and an ensemble. The forecast is the average of the three best candidates, ranked on up to twelve earlier folds and scored on the latest six, so its reported error is out-of-sample. Candidates now include damped-trend and level-adjusted seasonal models for series that are still ramping up. The baseline is chosen the same way, and the best-in-hindsight baseline is shown as a stricter reference.

WAPE · Weighted Absolute Percentage Error

WAPE expresses the sum of absolute forecast errors as a percentage of the total absolute actual values. It is volume-weighted: high-volume months contribute more than low-volume months. Lower is better.

WAPE (%) = 100 × Σ|Actualᵢ − Predictedᵢ| / Σ|Actualᵢ|

Example: absolute errors total 120 and actual volume totals 2,000 → WAPE = 6%. If all actual values sum to zero, WAPE is undefined; the backend may guard the denominator.

How rolling backtesting works

  1. Keep observations in chronological order; do not shuffle months randomly.
  2. For each fold, train on earlier months and predict the next month.
  3. Rank candidates using up to 12 earlier one-month-ahead folds.
  4. Select the best candidate combination (the forecast uses the top three).
  5. Evaluate the selected combination on the latest six later folds.
  6. Compare it with a simple baseline chosen in advance on the earlier folds. The hindsight-best baseline is shown only as a stricter diagnostic.

When history is too short to separate selection and evaluation periods, model selection may fall back to the test folds; performance then becomes optimistic and should be treated cautiously.

Loading project sales and break-even data…

Definition: estimated total investment = planned units × synthetic investment cost per unit. The break-even point is the first month cumulative recorded contract value sold reaches that threshold. A missing point means break-even was not reached during the observed data window (or the investment input is missing). This is a scenario estimate, not audited profit or accounting break-even.

Aligned project-level scenario: both sections use total investment = planned units × assumed cost per unit. Projected cumulative sales = historical cumulative contract value + forecast contract value for the selected horizon. Project-level ROI proxy = (projected cumulative sales − total investment) / total investment × 100; recovery = projected cumulative sales / total investment × 100. This is not accounting profit or audited ROI. Investment inputs are synthetic; replace them with verified costs before real decisions. Projected break-even is an extrapolation, not a guarantee.
